About CyberShield AI

Academic project documentation, architectural blueprints, methodology & specifications

1. Project Introduction & Problem Statement

Modern corporate networks generate overwhelming volumes of security alerts across firewalls, intrusion prevention systems, active directories, and cloud audit logs. Security analysts face alert fatigue, inconsistent event categorization, and lack of standardized severity ranking.

CyberShield AI solves this challenge by delivering an integrated, full-stack incident data analysis and visualization workbench. It provides automated 15-stage CSV ingestion, deterministic heuristic risk prioritization (0–100), interactive Chart.js visualizations, and dynamic ReportLab PDF audits.

2. Core Objectives & Scope

  • Dataset Normalization: Convert raw, irregular incident logs into clean, uniform schema structures with error isolation.
  • Persistent Storage: Provide safe, parameterized SQLite operations with transactional ACID safeguards.
  • Data Visualization: Surface interactive timelines, category doughnuts, severity bars, and day/hour activity heatmaps.
  • Deterministic Prioritization: Implement a clear, transparent 4-factor formula scoring system without black-box opacity.
  • Automated PDF Reporting: Dynamically generate executive security summaries using ReportLab.

3. System Architecture & Workflow

CyberShield AI follows a clean, decoupled MVC/Services architectural pattern:

[CSV Upload / REST API] → [Data Cleaning & Validation Service (Pandas)] → [SQLite Persistent Database (Parameterized & Indexed)] → [Analytics & Threat Prioritization Engine (NumPy)] → [Interactive Visualizations (Chart.js)] & [Audit PDF (ReportLab)]

State changes are strictly validated server-side. Errors are logged gracefully without leaking internal stack traces or database connection strings.

4. Academic Scope & Limitations

Important Disclaimer: CyberShield AI analyzes historical or logged incident datasets. It is not an inline packet sniffer, host firewall, or replacement for commercial Security Operations Center SIEMs. Synthetic sample records are clearly flagged as demonstration data.
Future Enhancements:
  • Integration with live Syslog / STIX / TAXII threat intelligence feeds.
  • Role-based access control (RBAC) with JWT session cookies and multi-factor authentication.
  • Automated SOAR (Security Orchestration, Automation, and Response) webhook triggers for IP blacklisting.
